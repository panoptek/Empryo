Add an OpenAI-compatible, Anthropic Messages, or OpenAI Responses API as a provider. No code, no plugin.

## Minimal example

Add this to `~/.soulforge/config.json` (or `.soulforge/config.json` for project scope):

```json
{
  "providers": [
    {
      "id": "together",
      "name": "Together AI",
      "baseURL": "https://api.together.xyz/v1",
      "envVar": "TOGETHER_API_KEY",
      "models": ["meta-llama/Llama-3-70b-chat-hf"]
    }
  ]
}
```

Set the key and use it:

```bash
soulforge --set-key together <your-key>
soulforge --model together/meta-llama/Llama-3-70b-chat-hf
```

## Fields

| Field | Required | What it does |
|-------|----------|--------------|
| `id` | yes | Used in model strings (`together/llama-3`) |
| `baseURL` | yes | API endpoint prefix (for example, `https://api.example.com/v1`) |
| `name` | — | Display name |
| `envVar` | — | Env var for the key (omit for auth-less servers) |
| `models` | — | Fallback model list (strings or `{id, name, contextWindow}`) |
| `modelsAPI` | — | Override the model-list URL; set to `false` if unavailable. Native APIs default to `{baseURL}/models`; OpenAI-compatible keeps its legacy `/models` default |
| `reasoning` | — | Thinking/reasoning config (see below) |
| `api` | — | Wire API: `"openai-compatible"` (default, `/chat/completions`), `"anthropic"` (`/messages`), `"openai-responses"` (`/responses`) |
| `maxTokensParam` | — | `"auto"` (default), `"max_tokens"` or `"max_completion_tokens"`. Auto sends `max_completion_tokens` for o1/o3/o4/gpt-5 models |
| `authHeader` | — | For `api: "anthropic"`: `"x-api-key"` (default) or `"bearer"` |
| `headers` | — | Extra HTTP headers sent with every request |

API keys and custom headers require HTTPS, except for `localhost`, `127.0.0.1`, and `[::1]` over HTTP. Requests carrying them do not follow redirects. This applies to model discovery and generation, including a custom `modelsAPI` URL.

<Accordion title="Anthropic-compatible endpoint">
  Use `api: "anthropic"` for servers that implement the Anthropic Messages API
  (`POST {baseURL}/messages`). Requests carry Anthropic prompt-caching breakpoints and native thinking/effort options.
  Model discovery uses `GET {baseURL}/models`; add `models` as a fallback when the server does not provide it.

  ```json
  {
    "providers": [{
      "id": "my-anthropic",
      "name": "My Anthropic-compatible API",
      "baseURL": "https://api.example.com/v1",
      "envVar": "MY_API_KEY",
      "api": "anthropic",
      "models": ["claude-sonnet-4-5-20250929"]
    }]
  }
  ```

  Add `"authHeader": "bearer"` if the server expects `Authorization: Bearer` instead of `x-api-key`.
  One host that serves several wire APIs can be registered once per API with different `id`s.
</Accordion>

<Accordion title="Reasoning models on /chat/completions">
  OpenAI reasoning models reject `max_tokens`. With the default `maxTokensParam: "auto"`, models whose id
  starts with `o1`/`o3`/`o4`/`gpt-5` get `max_completion_tokens`. Set it explicitly when your server
  uses different model names:

  ```json
  {
    "providers": [{
      "id": "my-openai",
      "baseURL": "https://api.example.com/v1",
      "envVar": "MY_API_KEY",
      "maxTokensParam": "max_completion_tokens"
    }]
  }
  ```
</Accordion>

## Thinking / reasoning

For models that support reasoning over an OpenAI-compatible endpoint, add a `reasoning` block. Three styles are supported — use the one your provider accepts:

```json
{
  "providers": [{
    "id": "dashscope",
    "baseURL": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "envVar": "DASHSCOPE_API_KEY",
    "models": ["qwen-plus"],
    "reasoning": {
      "enabled": true,
      "budget": 8192
    }
  }]
}
```

| Style | Fields | When to use |
|-------|--------|-------------|
| OpenAI-style | `effort: "low" \| "medium" \| "high" \| "xhigh" \| "none"` | OpenAI-compatible reasoning models |
| DashScope-style | `enabled: true`, `budget: 8192` | Alibaba Qwen, DashScope APIs |
| Raw | `extraParams: { ... }` | Anything else — fields are forwarded verbatim |

The fields are injected into every request body. Raw `extraParams` override all other keys on collision.

## Scope

- **Global** — `~/.soulforge/config.json` applies everywhere.
- **Project** — `.soulforge/config.json` overrides global entries with the same `id`.

## Conflicts

If your `id` matches a built-in (e.g. `"anthropic"`), SoulForge renames it to `{id}-custom` — the built-in is never replaced. Custom providers always show `[custom]` in `/keys` and `--list-providers`.
